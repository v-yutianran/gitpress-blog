用 GitPress 在 GitHub Pages 上搭建个人博客

背景

我想参考 GitPress.net，在自己的 GitHub 上搭一个博客，并先放三篇测试文章。

1. 了解 GitPress

GitPress.net 是一个基于 pnpm 的博客框架。文章和设置写在 Markdown 和 gitpress.json 里，由 GitHub Actions 构建成静态网站，再交给 GitHub Pages 托管。官方推荐用两个仓库：一个私有仓库放文章，一个公开仓库放构建好的网站。

2. 新建仓库并部署

电脑上的 gh 已经登录，所以直接用 gh 新建了仓库，没有在网页上手动建。

  • 用一个公开仓库代替官方的两个仓库：
    • source 分支放源码：gitpress.json、content/posts/、content/pages/about.md、media/，主题是 classic。
    • main 分支放构建产物，每次构建都会被整个覆盖，不要手动改。
  • 每次推送到 source，工作流就用 tap6/build-action@v1 构建，再用仓库自带的 token 推送到 main，不需要单独配置部署密钥。
  • GitHub Pages 从 main 分支的根目录提供网站。

三篇测试文章：

  1. 欢迎来到我的博客
  2. Markdown 写作测试（标题、列表、代码块、表格、引用）
  3. 第三篇测试文章

3. 换成根域名

网站一开始在 https://v-yutianran.github.io/gitpress-blog/。为了直接用 https://v-yutianran.github.io，做了这几件事：

  • 把仓库改名为 v-yutianran.github.io
  • 把 gitpress.json 里的站点地址改成 https://v-yutianran.github.io，基础路径改成 /
  • 重新构建并部署，用 curl 确认首页和三篇文章都返回 200

4. 一键发布的 skill

最后写了一个 gitpress-publish skill。以后只要给它一篇 md，它会：

  1. 补全 frontmatter（标题、日期、标签、摘要）
  2. 用英文 slug 保存到 content/posts/
  3. 推送到 source 分支，并等待构建和部署完成
  4. 检查文章能正常打开，再返回线上链接

注意事项

  • 仓库是公开的，draft: true 的草稿不会出现在网站上，但在源码里能被看到。想藏起来的话，可以改回官方的一私一公两个仓库。
  • 不要手动编辑 main 分支。
